# Quality checks and live-demo monitoring

Run `pnpm quality` for strict TypeScript checking, ESLint with TypeScript, React Hooks and JSX accessibility rules, Prettier verification, and Vitest V8 coverage. Run `pnpm build` separately. CI runs the same gates plus ShellCheck for executable scripts. Its separate ecosystem job bootstraps the disposable lab and runs integration, recovery, learning and browser checks sequentially. Formatting and lint results are pass/fail: they do not have a meaningful quality percentage. Coverage reports lines, branches, functions, and statements; no artificial combined score is created.

`pnpm test:coverage` measures the entire configured TypeScript/TSX application/package/tool scope, including untouched files. Documentation, SVG/Excalidraw assets, generated output and dependencies contain no application code and are outside that scope. Non-TypeScript operational sources (shell scripts, SQL migrations and report scripts) are checked separately; this is not an all-language coverage claim.

The same run computes a **91% business line gate**, strictly above 90%, from the explicit file list in `coverage-scope.mjs`. That scope contains ordering/fulfillment domain modules and policies, catalog cache rules, public contracts/validation, the typed request wrapper, observed-journey interpretation, shopper policy, feeder recovery and fault-experiment policy. It excludes HTTP route assembly, JSX rendering, entrypoints, host/process control implementation and generic infrastructure. The overall report retains those exclusions, including zero-covered files; no file is removed from overall to improve a percentage. New business modules must join the reviewed list. Missing listed files fail report generation.

Reports: `coverage/index.html` (all configured files), `coverage/coverage-summary.json`, `coverage/system-summary.json`, [committed per-system report](coverage-report.md), [all file metrics and both scopes](coverage-snapshot.json), and separate business/overall SVG badges. Aggregates weight covered/total lines, rather than averaging percentages. Per-system rows use non-overlapping workspace folders; operator-owned feeder/experiment/lifecycle tools appear in the tools row. The operator application row measures HTTP assembly separately. CI uploads the same reports and both badges even when a gate fails; the committed badges change only with a committed measured run. Codecov, when enabled, receives overall LCOV.

Tests exercise public module interfaces. The checkout/fulfillment module suite applies real owner migrations to **PGlite 0.5.8**, an embedded PostgreSQL engine used only in tests. SQL failures verify transactional rollback and outgoing-event atomicity. It uses one embedded connection per fixture: multi-connection contention, real server versions, broker delivery and reconnect require the existing container integration/recovery suite. Owner data inspection verifies committed records, not private helper calls. Shopper checks exercise the real typed client against an HTTP transport fixture. Host operations in fault-policy tests are simulated so unit tests never terminate developer processes. Runtime logs/state are isolated in temporary directories.

The covered scenarios include confirmed preview acceptance, changed contents/prices, empty/inactive/short-stock rejection, accepted replay and conflicting key reuse, immutable snapshots, failed storage rollback, duplicate/contradictory outcomes, exactly-once compensation, historical recovery carts, durable attempt resumption, paused queues, dependency outages, retry deadlines/budget, all nine fault policies and explicit restoration, shopper stop/abandonment/rejection/unknown recovery, cache fill failure, bounded read retries and cancellation. Integration/browser tests remain separate correctness evidence. A coverage line being executed does not prove every branch or concurrency guarantee.

## Host observation with btop

Run `./lab monitor`, `./scripts/monitor` or `pnpm monitor` in a separate terminal on the machine being measured. It opens btop without stopping the lab. On macOS install with `brew install btop`. In a Debian/Ubuntu VM install with `sudo apt update` followed by `sudo apt install btop`. Other Linux distributions should use their package manager. The helper checks availability and does not install or change machine configuration.

Observe CPU, memory, disk, network, and process activity during seeded checkouts and failure/retry presets. Run btop on application host for the frontend/backend host, on remote host macOS for the physical host, and inside its Linux VM for guest resource use. Guest figures do not prove physical-host usage. Hardware sensor/GPU measurements depend on platform support and permissions; record unavailable fields as unavailable. btop is an interactive observer, not a telemetry storage/export pipeline. Use the application dashboard for business activity and `docker stats --no-stream` for container measurements. Record sample time, machine, workload, and topology when comparing observations.

A separate Dependency and publication checks job runs `pnpm security`: current-file policy, npm advisories and Git-history secret detection. Container-package findings are checked separately with `pnpm security:images`; they are not included in the coverage percentage or that job. See [the recorded scan](security.md).

Sources: [Vitest coverage](https://vitest.dev/guide/coverage), [JSX accessibility rules](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y), [Codecov action](https://github.com/codecov/codecov-action), [btop](https://github.com/aristocratos/btop).

Coverage collected after the Vitest 4 upgrade uses its current V8 reporting semantics. Percentages from earlier tool versions are historical measurements and should not be interpreted as a direct coverage trend without rerunning both versions on the same source.
